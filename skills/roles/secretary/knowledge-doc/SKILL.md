# Knowledge — длинные документы инстанса

`secretary-instance/state/knowledge/` это место для длинного рассуждения и контекста:
брейнштормы, журналы решений, разборы инцидентов. Документы едут на приватный remote вместе с
остальным checkpoint, поэтому переживают переезд на новую машину.

## Куда что писать

- Исполняемая работа (карточки, спеки, статусы) — доска Pipeline, скилл `spec-card`.
- Короткий актуальный вывод, который должен попасть голове в контекст — curated memory
  (`state/memory/facts`), пишет куратор.
- Длинное рассуждение и контекст, из которого вывод получился — сюда.

Knowledge не индексируется, в `memory_search` не попадает и в контекст голов целиком не грузится.
Документ читают адресно, когда нужна история вопроса.

## Как писать

```bash
python3 -m secretary knowledge write --instance ~/secretary-instance --actor secretary \
  --path decisions/2026-07-25-sprint-1.md --file /tmp/sprint-1.md
python3 -m secretary knowledge list --instance ~/secretary-instance
```

**Сырой `git add`/`git commit` в инстанс-репо не делай.** Тиковый писатель диспетчера коммитит
`state/board` и `state/runs` в тот же репозиторий каждую минуту; ручной коммит с ним гоняется.
`knowledge write` берёт общий writer lock и коммитит только `state/knowledge`.

- `--path` относительный, внутри `state/knowledge`, обязательно `.md`. Раздел выбирай по типу
  документа: `brainstorms/`, `decisions/`, `incidents/`.
- `--file` это полный новый текст документа: команда перезаписывает файл целиком, а не дописывает.
  Правишь документ — держи рабочую копию (например в `/tmp`), правь её и записывай снова.
- Формат свободный, frontmatter и метаданные не нужны.
- Запись того же содержимого второй раз отдаёт `changed: false` и коммита не делает.
- Документ с секретом отклоняется (`error: validation`, код 2) и на диск не попадает. Убери
  токен из текста, не обходи проверку.
